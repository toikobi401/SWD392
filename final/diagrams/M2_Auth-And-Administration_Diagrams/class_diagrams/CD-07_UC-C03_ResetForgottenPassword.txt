@startuml
title CD-07 UC-C03 Reset Forgotten Password

skinparam classAttributeIconSize 0
hide empty members

class ForgotPasswordPage <<boundary>> {
    + request(e)
    + reset(e)
}

class AuthController <<boundary>> {
    + forgotPassword(req, res)
    + resetPassword(req, res)
    + assertPasswordStrength(password)
    + record(entry)
}

class User <<entity>> {
    - _id : ObjectId
    - email : String
    - passwordHash : String
    - failedLoginAttempts : Number
    - status : AccountStatus
    + findOne(filter) : Query<User>
    + select(fields) : Query<User>
    + save() : Promise<User>
}

class EmailService <<external>> {
    + sendOtp(to, otp, channel)
}

enum AccountStatus <<enumeration>> {
    PENDING_VERIFICATION
    ACTIVE
    LOCKED
    DEACTIVATED
}

ForgotPasswordPage ..> AuthController : POST /api/auth/forgot-password\nPOST /api/auth/reset-password
AuthController ..> User
AuthController ..> EmailService : EMAIL channel
User --> AccountStatus : status

note bottom of AuthController
    AuthService and audit logic are folded into this boundary.
    Both endpoints are public. An unknown email returns the same
    200 message as a successful OTP request; delivery failure returns 500.
end note

note bottom of User
    Only actual schema attributes are listed.
    resetOtpHash and resetOtpExpiresAt are not in userSchema.
    Dynamic assignments made by requestPasswordReset() are not persisted.
    SD-07 labels the intended success branch as conditional on valid
    OTP fields being available; the current schema prevents that flow.
    select() is a Mongoose query-chain operation.
end note

note bottom of EmailService
    NotificationProxy.sendOtp() represents this external call.
    The UI uses EMAIL; the service also accepts SMS.
    Development without a configured provider logs the OTP.
end note
@enduml
